# 聊天界面组件设计

> 本文档详细介绍各 UI 组件的设计思路、交互逻辑和实现细节。

---

## 一、组件总览

```
App.tsx (根组件)
  LoginPage            登录/注册页（未登录时显示）
  Sidebar              侧边栏（会话列表 + 用户信息）
  MessageList          消息列表（气泡 + Markdown）
    MarkdownRenderer   Markdown 渲染器
  InputArea            输入区域（TextArea + 发送按钮）
```

每个组件职责单一，通过 props 接收数据和回调，自身不做数据请求（全部通过 Hook 处理）。

## 二、LoginPage 登录/注册页

`components/LoginPage/index.tsx`

### 功能
* 一个页面同时支持登录和注册（通过 `mode` 状态切换）
* 使用 Ant Design Form 组件，自带校验
* 错误信息显示在表单上方 + 顶部全局提示

### 实现要点

```typescript
const [mode, setMode] = useState<"login" | "register">("login");

const handleSubmit = async (values: { email: string; password: string }) => {
  try {
    if (mode === "login") {
      await onLogin(values.email, values.password);
    } else {
      await onRegister(values.email, values.password);
    }
  } catch (e) {
    setError((e as Error).message);
    message.error(msg);  // Ant Design 全局提示
  }
};
```

### 表单校验
```tsx
<Form.Item
  name="email"
  rules={[
    { required: true, message: "请输入邮箱" },
    { type: "email", message: "邮箱格式不正确" },
  ]}
>
  <Input placeholder="邮箱" />
</Form.Item>

<Form.Item
  name="password"
  rules={[
    { required: true, message: "请输入密码" },
    { min: 8, message: "密码至少 8 位" },
  ]}
>
  <Input.Password placeholder="密码" />

```

Ant Design Form 的 `rules` 属性自动校验输入：邮箱格式、密码最小长度。校验不通过时自动在输入框下方显示错误提示。

### 视觉设计
* 居中卡片布局
* 顶部绿色机器人图标
* 登录/注册切换链接
* 主色调绿色按钮（`--accent: #10a37f`）

## 三、Sidebar 侧边栏

`components/Sidebar/index.tsx`

### 功能
* 顶部：新建对话按钮
* 中间：会话列表（使用 Ant Design Menu 组件）
* 底部：用户邮箱 + 登出按钮

### 新建对话按钮的行为

点击“新建对话”不会立即调用后端，也不会在侧边栏插入一条空记录。它只让应用进入草稿态：

```typescript
const handleNewSession = useCallback(() => {
  if (isCreatingConversation) return;  // 首条消息正在落库时不重复切换
  if (isLoading) stop();  // 生成中先中断旧流，避免继续写入新草稿
  setActiveId(null);      // 不选中任何已有对话
}, [isCreatingConversation, isLoading, setActiveId, stop]);
```

`useChat(null)` 的历史加载 effect 会清空消息区。用户发送第一条消息时，`handleSend` 才创建数据库记录并调用聊天接口。这样“新建对话”和“未选中对话时直接发送”共享同一条资源创建路径，避免产生空会话。

### 会话列表实现

```typescript
const items = sessions.map((s) => ({
  key: String(s.id),       // Menu key 必须是 string
  icon: <MessageOutlined />,
  label: (
    <div style={{ display: "flex", justifyContent: "space-between" }}>
      <span style={{ overflow: "hidden", textOverflow: "ellipsis", whiteSpace: "nowrap" }}>
        {s.title}
      </span>
      <DeleteOutlined
        onClick={(e) => {
          e.stopPropagation();  // 阻止冒泡，避免同时触发菜单选中
          onDelete(s.id);
        }}
      />
    </div>
  ),
}));

<Menu
  mode="inline"
  selectedKeys={activeSessionId ? [String(activeSessionId)] : []}
  items={items}
  onClick={({ key }) => onSelect(Number(key))}
/>
```

### 关键交互细节

**标题省略：** 对话标题可能很长，用 `text-overflow: ellipsis` 超长时显示省略号。

**删除按钮阻止冒泡：** 删除按钮在 Menu 的 label 内，点击时 `e.stopPropagation()` 阻止事件冒泡到 Menu，避免点击删除同时触发菜单选中。

**selectedKeys：** Ant Design Menu 通过 `selectedKeys` 控制高亮项，需要用 string 格式。

### 视觉设计
* 浅灰色背景（`--sidebar-bg: #f9f9f9`）
* 菜单项 hover 时加深背景
* 退出按钮使用 `type="text"` 的透明按钮

## 四、MessageList 消息列表

`components/MessageList/index.tsx`

### 功能
* 消息气泡展示（用户右对齐，AI 左对齐）
* AI 消息用 Markdown 渲染
* 用户消息用纯文本
* 生成中显示打字指示器（三个跳动的点）
* 自动滚动到底部
* 空状态显示欢迎界面

### 消息渲染逻辑

```tsx
{messages.map((msg) => {
  const isUser = msg.role === "user";
  return (
    <div className={`${styles.messageRow} ${isUser ? styles.messageRowUser : ""}`}>
      {/* 头像：用户深色，AI 绿色 */}
      <Avatar icon={isUser ? <UserOutlined /> : <RobotOutlined />} />

      {/* 消息气泡 */}
      <div className={`${styles.bubble} ${isUser ? styles.bubbleUser : styles.bubbleAssistant}`}>
        {msg.role === "assistant" ? (
          /* AI 消息：有内容渲染 Markdown，无内容且加载中显示打字指示器 */
          msg.content ? (
            <MarkdownRenderer content={msg.content} />
          ) : isLoading ? (
            <TypingIndicator />
          ) : null
        ) : (
          /* 用户消息：纯文本，保留换行 */
          <span style={{ whiteSpace: "pre-wrap" }}>{msg.content}</span>
        )}
      </div>
    </div>
  );
})}
```

### 三种渲染分支

1. **AI 有内容**：`<MarkdownRenderer content={msg.content} />` 渲染 Markdown
2. **AI 无内容 + 加载中**：显示三个跳动的圆点（等待 LLM 响应）
3. **用户消息**：纯文本 `whiteSpace: "pre-wrap"` 保留换行

### 自动滚动

```typescript
const bottomRef = useRef<HTMLDivElement>(null);

useEffect(() => {
  bottomRef.current?.scrollIntoView({ behavior: "smooth" });
}, [messages]);
```

`messages` 变化时（新消息或流式追加内容），自动平滑滚动到底部。这让用户在 AI 回复时始终看到最新内容。

### 空状态

```tsx
if (messages.length === 0) {
  return (
    <div className={styles.empty}>
      <RobotOutlined className={styles.emptyIcon} />
      <h2>有什么可以帮你</h2>
      <p>输入消息，开始对话</p>
    </div>
  );
}
```

没有消息时显示欢迎界面，引导用户开始对话。

## 五、MarkdownRenderer 渲染器

`components/MarkdownRenderer/index.tsx`

### 功能
* 将 AI 回复的 Markdown 文本渲染为格式化的 HTML
* 支持代码块语法高亮
* 支持 GitHub 扩展语法（表格、删除线、任务列表）

### 实现

```typescript
import ReactMarkdown from "react-markdown";
import remarkGfm from "remark-gfm";
import { Prism as SyntaxHighlighter } from "react-syntax-highlighter";
import { oneDark } from "react-syntax-highlighter/dist/esm/styles/prism";

export default function MarkdownRenderer({ content }: { content: string }) {
  return (
    <ReactMarkdown
      remarkPlugins={[remarkGfm]}
      components={{
        code({ className, children, ...props }) {
          const match = /language-(\w+)/.exec(className || "");
          const isInline = !className;

          if (isInline) {
            return <code className={className} {...props}>{children}</code>;
          }

          return (
            <SyntaxHighlighter
              style={oneDark}
              language={match ? match[1] : "text"}
              PreTag="pre"
            >
              {String(children).replace(/\n$/, "")}
            </SyntaxHighlighter>
          );
        },
      }}
    >
      {content}
    </ReactMarkdown>
  );
}
```

### 库的分工

| 库 | 作用 |
|------|------|
| react-markdown | 核心：解析 Markdown 字符串为 React 元素 |
| remark-gfm | 插件：支持 GitHub 扩展语法 |
| react-syntax-highlighter | 代码块语法高亮渲染 |
| oneDark | 语法高亮主题（暗色） |

### 行内代码 vs 代码块

Markdown 中有两种代码：

```
这是 `行内代码` 在句子中。
```

```python
# 这是代码块
print("hello")
```

react-markdown 渲染 `code` 元素时，通过 `className` 区分：
* 有 `className`（如 `language-python`）-> 代码块，用 SyntaxHighlighter
* 无 `className` -> 行内代码，用普通 `<code>` 标签

### 流式渲染中的 Markdown 处理

AI 回复是逐 token 到达的，可能到一半时 Markdown 不完整（如代码块只有开头没有结尾）。

react-markdown 足够健壮，会自动处理不完整的 Markdown：
* 不完整的代码块会被当作普通文本显示
* 下一个 token 到来后，Markdown 完整了，自动重新渲染为正确的格式

用户在打字机效果中看到的就是：文本先以普通格式出现，Markdown 标记完成后变为格式化版本。

## 六、输入区设计

输入区直接写在 `App.tsx` 中（没有单独抽组件）：

```tsx
<div className={styles.inputArea}>
  <div className={styles.inputContainer}>
    <div className={styles.inputWrapper}>
      <TextArea
        value={input}
        onChange={(e) => handleInputChange(e.target.value)}
        onPressEnter={(e) => {
          if (!e.shiftKey) {
            e.preventDefault();
            handleSend();
          }
        }}
        placeholder="发送消息"
        autoSize={{ minRows: 1, maxRows: 6 }}
        disabled={isLoading}
        variant="borderless"
      />
      {isLoading ? (
        <Button type="primary" danger icon={<StopOutlined />} onClick={stop} />
      ) : (
        <Button
          type="primary"
          icon={<SendOutlined />}
          onClick={handleSend}
          disabled={!input.trim()}
        />
      )}
    </div>
    <p className={styles.inputHint}>AI 可能会犯错，请核实重要信息</p>
  </div>
</div>
```

### 交互细节

**Enter 发送，Shift+Enter 换行：**
```typescript
onPressEnter={(e) => {
  if (!e.shiftKey) {  // 只有 Enter（不带 Shift）才发送
    e.preventDefault();
    handleSend();
  }
  // Shift+Enter 不拦截，TextArea 默认换行
}}
```

**自动高度：** `autoSize={{ minRows: 1, maxRows: 6 }}`，输入少时 1 行，输入多时最多扩展到 6 行。

**动态按钮：** 生成中显示红色停止按钮（调用 `stop` 中断），空闲时显示发送按钮。发送按钮在输入为空或正在创建新对话时禁用，创建中会显示 loading 状态。

**圆角胶囊设计：** 输入框和按钮放在一个圆角容器内（ChatGPT 风格），`variant="borderless"` 去掉 TextArea 自带边框。

## 七、发送消息的完整流程

```typescript
const handleSend = useCallback(async () => {
  if (isCreatingConversation || isLoading || !input.trim()) return;

  let conversationIdToSend = activeId;

  // 没有活跃对话时，先创建一条对话记录
  if (!activeId) {
    setIsCreatingConversation(true);
    try {
      const conversation = await createConversation();
      conversationIdToSend = conversation.id;
    } finally {
      setIsCreatingConversation(false);
    }
  }

  if (conversationIdToSend === null) return;

  // 显式传入新对话 ID，不等待 activeId 触发下一轮渲染
  await sendMessage(conversationIdToSend);
  await refreshConversations();  // 同步标题更新
}, [/* 相关状态和回调 */]);
```

### 显式传入对话 ID 的原因

草稿对话落库后 `activeId` 通过 `setActiveId` 更新，但 React 状态更新是异步的。如果立刻调用不传参的 `sendMessage()`，它捕获到的 `conversationId` 可能仍是 `null`。

现在的实现让 `sendMessage` 接受可选的 `targetConversationId` 参数。创建接口返回新对话对象后，`handleSend` 直接把 `conversation.id` 传给 `sendMessage`，发送不依赖下一轮渲染，也没有 `setTimeout` 竞态。

同时，`isCreatingConversation` 会禁用输入框和发送按钮，避免用户在创建请求返回前连续按 Enter 创建多条空对话。

### refreshConversations 的作用

发送消息后刷新侧边栏列表，因为后端可能在首条消息时自动更新了对话标题（从"新对话"变为消息内容前 50 字）。刷新后侧边栏显示更新后的标题。
