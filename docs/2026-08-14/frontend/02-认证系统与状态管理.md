# 认证系统与状态管理

> 本文档详细介绍前端的 JWT 认证流程、API 封装层、以及三个核心 Hook 的设计。

---

## 一、API 工具层 lib/api.ts

这是前端与后端通信的唯一入口，所有 HTTP 请求都经过这里。

### 1.1 JWT Token 管理

```typescript
const TOKEN_KEY = "chat_token";

export function getToken(): string | null {
  return localStorage.getItem(TOKEN_KEY);
}

export function setToken(token: string): void {
  localStorage.setItem(TOKEN_KEY, token);
}

export function clearToken(): void {
  localStorage.removeItem(TOKEN_KEY);
}
```

Token 存在 `localStorage` 中，key 为 `"chat_token"`。

**为什么用 localStorage 而不是 Cookie？**
* 前后端分离项目，用 JS 管理 token 更灵活
* 可以精确控制什么时候发送 token（只发到 /api 路径）
* Cookie 需要 SameSite/Secure 配置，更复杂

### 1.2 统一请求封装 apiFetch

```typescript
export async function apiFetch<T>(
  path: string,
  options: RequestInit = {},
): Promise<T> {
  const token = getToken();
  const headers: Record<string, string> = {
    "Content-Type": "application/json",
    ...(options.headers as Record<string, string>),
  };
  if (token) {
    headers["Authorization"] = `Bearer ${token}`;
  }

  const res = await fetch(`${API_BASE}${path}`, { ...options, headers });

  if (!res.ok) {
    let detail = "";
    try {
      const body = await res.json();
      detail = body.detail || JSON.stringify(body);
    } catch {
      detail = await res.text();
    }
    throw new Error(detail || `HTTP ${res.status}`);
  }

  if (res.status === 204) return undefined as T;
  return res.json();
}
```

**核心功能：**
* 自动从 localStorage 读取 token 并附加到请求头
* 统一错误处理：非 2xx 响应解析错误信息并抛出异常
* 204 No Content 特殊处理（没有响应体）
* 泛型 `<T>`：调用方指定响应类型，TypeScript 自动推断

### 1.3 认证 API

```typescript
export const authApi = {
  register: (email: string, password: string) =>
    apiFetch("/auth/register", {
      method: "POST",
      body: JSON.stringify({ email, password }),
    }),

  login: async (email: string, password: string) => {
    // fastapi-users 登录用 OAuth2 表单格式（非 JSON）
    const formData = new URLSearchParams();
    formData.append("username", email);
    formData.append("password", password);
    const res = await fetch(`${API_BASE}/auth/jwt/login`, {
      method: "POST",
      body: formData,
    });
    if (!res.ok) throw new Error("邮箱或密码错误");
    const data = await res.json();
    setToken(data.access_token);
  },

  getMe: () => apiFetch<User>("/users/me"),
};
```

### 为什么登录不用 apiFetch

fastapi-users 的登录接口要求 **OAuth2 密码模式**的请求格式：
* Content-Type 是 `application/x-www-form-urlencoded`（不是 JSON）
* 字段名是 `username`（不是 `email`）

所以登录单独写一个 fetch，用 `URLSearchParams` 构建表单数据。登录成功后拿到 `access_token` 并存入 localStorage。

### 1.4 对话 API

```typescript
export const conversationApi = {
  list: () => apiFetch<Conversation[]>("/conversations"),
  create: (title?: string) =>
    apiFetch<Conversation>("/conversations", {
      method: "POST",
      body: JSON.stringify(title ? { title } : {}),
    }),
  getMessages: (id: number) =>
    apiFetch<Message[]>(`/conversations/${id}/messages`),
  delete: (id: number) =>
    apiFetch<void>(`/conversations/${id}`, { method: "DELETE" }),
};
```

## 二、认证 Hook useAuth

`hooks/useAuth.ts` 管理登录状态：

```typescript
export function useAuth() {
  const [user, setUser] = useState<User | null>(null);
  const [loading, setLoading] = useState(true);

  // 应用启动时检查 token 有效性
  useEffect(() => {
    const token = getToken();
    if (!token) {
      setLoading(false);
      return;
    }
    // 有 token，验证是否仍然有效
    authApi
      .getMe()
      .then(setUser)
      .catch(() => clearToken())  // token 过期则清除
      .finally(() => setLoading(false));
  }, []);

  // 登录
  const login = useCallback(async (email, password) => {
    await authApi.login(email, password);  // 获取并存储 token
    const me = await authApi.getMe();       // 获取用户信息
    setUser(me);
  }, []);

  // 注册后自动登录
  const register = useCallback(async (email, password) => {
    await authApi.register(email, password);
    await authApi.login(email, password);  // 注册成功后自动登录
    const me = await authApi.getMe();
    setUser(me);
  }, []);

  // 登出
  const logout = useCallback(() => {
    clearToken();
    setUser(null);
  }, []);

  return { user, loading, login, register, logout };
}
```

### 状态设计

* `user: User | null`：当前用户信息，null 表示未登录
* `loading: boolean`：初始化时检查 token 的状态，防止闪烁

### App.tsx 如何使用

```typescript
const { user, loading } = useAuth();

if (loading) return <Spin />;        // token 验证中
if (!user) return <LoginPage />;     // 未登录
return <ChatInterface />;             // 已登录
```

### 自动恢复登录态

用户刷新页面后，`localStorage` 中的 token 仍然存在。`useEffect` 在应用启动时用 token 调 `/users/me`，如果成功就恢复登录态。如果 token 过期（1小时后），清掉 token 显示登录页。

### 注册后自动登录

注册成功后直接调 `login`，用户不需要再手动输入邮箱密码登录。这是常见的产品体验优化。

## 三、对话管理 Hook useConversations

`hooks/useConversations.ts` 管理会话列表：

```typescript
export function useConversations(enabled: boolean) {
  const [conversations, setConversations] = useState<Conversation[]>([]);
  const [activeId, setActiveId] = useState<number | null>(null);

  const refresh = useCallback(async () => {
    const list = await conversationApi.list();
    setConversations(list);
    return list;
  }, []);

  // 用户登录后自动加载
  useEffect(() => {
    if (enabled) refresh().catch(() => {});
  }, [enabled, refresh]);

  const create = useCallback(async () => {
    const conv = await conversationApi.create();
    setConversations((prev) => [conv, ...prev]);  // 插入到列表顶部
    setActiveId(conv.id);                          // 草稿首次发送时选中
    return conv;
  }, []);

  const remove = useCallback(async (id: number) => {
    await conversationApi.delete(id);
    setConversations((prev) => prev.filter((c) => c.id !== id));
    setActiveId((prev) => (prev === id ? null : prev));  // 删除当前对话则清空选中
  }, []);

  return { conversations, activeId, setActiveId, refresh, create, remove };
}
```

### `enabled` 参数的作用

`useConversations(!!user)` —— 只在用户登录后才加载对话。未登录时 `enabled` 为 false，`useEffect` 不发请求。

### 创建时机

`create` 不由“新建对话”按钮直接调用。按钮只把 `activeId` 设为 `null`，进入草稿态；当用户在草稿态发送第一条消息时，`handleSend` 才调用 `create` 并使用返回的对话 ID 请求聊天接口。

### 状态更新策略

所有操作都用**局部更新**（直接修改 state），而不是重新请求整个列表：
* 创建：`setConversations((prev) => [conv, ...prev])`
* 删除：`setConversations((prev) => prev.filter(...))`

只有在需要同步后端更改（如标题自动更新）时才调 `refresh`。

## 四、三个 Hook 的协作关系

```
App.tsx
  │
  ├── useAuth()
  │     └── user, login, register, logout
  │
  ├── useConversations(!!user)
  │     └── conversations, activeId, create, remove
  │           │
  │           ▼ activeId 变化触发
  │
  └── useChat(activeId)
        └── messages, input, sendMessage, stop
```

认证状态（`user`）驱动对话管理的启用；活跃对话（`activeId`）驱动聊天 Hook 加载对应历史。三个 Hook 形成了一条依赖链，每一环的变化自动传递到下一环。

这就是 React 的核心思想：**状态驱动 UI**。不需要手动控制流程，改变 state 后 React 自动重新渲染。
