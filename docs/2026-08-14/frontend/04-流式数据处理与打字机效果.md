# 流式数据处理与打字机效果

> 本文档详细介绍 useChat Hook 中的 SSE 流式数据接收、解析、以及打字机效果的完整实现。
> 这是整个前端最核心、最复杂的部分。

---

## 一、useChat Hook 概览

`hooks/useChat.ts` 封装了聊天的全部逻辑：

```typescript
export function useChat(conversationId: number | null) {
  const [messages, setMessages] = useState<Message[]>([]);
  const [input, setInput] = useState("");
  const [isLoading, setIsLoading] = useState(false);
  const abortRef = useRef<AbortController | null>(null);
  const activeSendConversationIdRef = useRef<number | null>(null);

  // 切换对话时加载历史
  useEffect(() => { ... }, [conversationId]);

  // 发送消息（核心）
  const sendMessage = useCallback(
    async (targetConversationId?: number) => { ... },
    [],
  );

  // 中断生成
  const stop = useCallback(() => { ... }, []);

  return { messages, input, isLoading, handleInputChange, sendMessage, stop };
}
```

`conversationId` 是入参：对话切换时父组件传入新的 ID，触发 `useEffect` 加载历史。

`sendMessage` 还可以接收 `targetConversationId`。当用户未选中对话直接发送时，App 先创建对话，再把新 ID 显式传给 `sendMessage`，避免等待 `conversationId` prop 完成下一轮渲染。

## 二、切换对话时加载历史

```typescript
useEffect(() => {
  if (!conversationId) {
    setMessages([]);  // 没有选中对话时清空消息
    return;
  }

  // 新对话创建后立即发送时，跳过空历史加载
  if (activeSendConversationIdRef.current === conversationId) {
    return;
  }

  let cancelled = false;  // 防止组件卸载后 setState
  conversationApi
    .getMessages(conversationId)
    .then((serverMsgs) => {
      // 发送已经开始时，不能用历史响应覆盖本地流式内容
      if (
        !cancelled &&
        activeSendConversationIdRef.current !== conversationId
      ) {
        setMessages(
          serverMsgs.map((m) => ({
            id: String(m.id),     // 后端 int id 转为 string
            role: m.role,
            content: m.content,
          })),
        );
      }
    })
    .catch(() => {
      if (
        !cancelled &&
        activeSendConversationIdRef.current !== conversationId
      ) {
        setMessages([]);
      }
    });

  return () => { cancelled = true; };  // 清理函数
}, [conversationId]);
```

### `cancelled` 标志的作用

React 组件卸载（如切换对话）后，异步请求可能还在进行。如果请求返回时组件已卸载，`setMessages` 会报错（内存泄漏警告）。

`cancelled` 标志在 cleanup 函数中设为 true，请求返回时检查：如果已卸载就不更新 state。

### 类型转换

后端返回的 `ServerMessage.id` 是 `number`，前端 `Message.id` 是 `string`（为了兼容临时消息）。加载历史时需要 `String(m.id)` 转换。

## 三、SSE 消息解析

### 3.1 SSE 数据格式

后端发送的 SSE 数据格式：
```
data: {"content": "你好"}\n\n
data: {"content": "！"}\n\n
data: [DONE]\n\n
```

每条消息以 `data: ` 开头，以 `\n\n`（空行）结尾。

### 3.2 解析函数 parseSSEChunk

```typescript
function parseSSEChunk(chunk: string): {
  content: string | null;
  error: string | null;
  done: boolean;
} {
  const data = chunk.replace(/^data:\s*/, "").trim();

  if (data === "[DONE]") {
    return { content: null, error: null, done: true };
  }

  try {
    const parsed = JSON.parse(data);
    if (parsed.error) {
      return { content: null, error: parsed.error, done: false };
    }
    return { content: parsed.content ?? "", error: null, done: false };
  } catch {
    return { content: null, error: null, done: false };
  }
}
```

处理三种情况：
1. `[DONE]` -> 回复结束
2. `{"error": "..."}` -> LLM 出错
3. `{"content": "..."}` -> 正常文本片段

JSON 解析失败时（数据不完整）静默跳过，返回空结果。

## 四、发送消息的完整流程

`sendMessage` 是整个前端最复杂的函数：

```typescript
const sendMessage = useCallback(async () => {
  if (!conversationId) return;
  const text = input.trim();
  if (!text || isLoading) return;

  // === 步骤 1: 立即更新 UI ===
  const userMsg: Message = {
    id: generateId(),
    role: "user",
    content: text,
  };
  const assistantMsg: Message = {
    id: generateId(),
    role: "assistant",
    content: "",  // 空内容占位
  };
  setMessages((prev) => [...prev, userMsg, assistantMsg]);
  setInput("");
  setIsLoading(true);

  // === 步骤 2: 创建中断控制器 ===
  const controller = new AbortController();
  abortRef.current = controller;

  try {
    // === 步骤 3: 发送请求 ===
    const res = await fetch("/api/chat", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${getToken()}`,
      },
      body: JSON.stringify({
        conversation_id: chatConversationId,
        message: text,
      }),
      signal: controller.signal,
    });

    if (!res.ok) throw new Error(await res.text());

    // === 步骤 4: 读取流式响应 ===
    const reader = res.body!.getReader();
    const decoder = new TextDecoder();
    let buffer = "";

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      buffer += decoder.decode(value, { stream: true });

      const parts = buffer.split("\n\n");
      buffer = parts.pop() || "";

      for (const part of parts) {
        const trimmed = part.trim();
        if (!trimmed) continue;

        const { content, error, done: isDone } = parseSSEChunk(trimmed);
        if (isDone) break;
        if (error) throw new Error(error);
        if (content) {
          // === 步骤 5: 追加内容到 AI 消息 ===
          setMessages((prev) => {
            return prev.map((item) =>
              item.id === assistantMsg.id
                ? { ...item, content: item.content + content }
                : item,
            );
          });
        }
      }
    }
  } catch (e) {
    const err = e as Error;
    if (err.name !== "AbortError") {
      // 真实错误：显示在 AI 气泡中
      setMessages((prev) => {
        return prev.map((item) =>
          item.id === assistantMsg.id && !item.content
            ? { ...item, content: "[请求失败] " + err.message }
            : item,
        );
      });
    }
    // AbortError（用户主动中断）：静默处理
  } finally {
    setIsLoading(false);
    abortRef.current = null;
    activeSendConversationIdRef.current = null;
  }
}, [conversationId, input, isLoading]);
```

## 五、核心 API 详解

### 5.1 ReadableStream + getReader()

普通 fetch 的响应是一次性返回的：`const data = await res.json()`。

流式响应不同，`res.body` 是一个 `ReadableStream`，数据分块陆续到达：

```typescript
const reader = res.body!.getReader();

while (true) {
  const { done, value } = await reader.read();
  // done: true 表示流结束
  // value: Uint8Array（二进制字节）
  if (done) break;
  // 处理 value...
}
```

### 5.2 TextDecoder：二进制到字符串

`reader.read()` 返回的 `value` 是 `Uint8Array`（原始字节），不是字符串。`TextDecoder` 负责转换：

```typescript
const decoder = new TextDecoder();  // 默认 UTF-8
const text = decoder.decode(bytes);  // Uint8Array -> string
```

### 5.3 `{ stream: true }`：处理多字节字符截断

中文字符在 UTF-8 中占 3 个字节。网络分块可能在字节中间截断：

```
"你" 的 UTF-8 字节: [228, 189, 160]

第 1 次 read: [228, 189]        ← 不完整
第 2 次 read: [160, ...]        ← 补全
```

不加 `{ stream: true }`：每次独立解码会产生乱码。
加了 `{ stream: true }`：decoder 内部缓存不完整的字节，下次拼上再解码。

```typescript
// 第一次: decode([228, 189], { stream: true }) -> ""（缓存这 2 个字节）
// 第二次: decode([160, ...], { stream: true }) -> "你"（拼上缓存的字节）
```

### 5.4 buffer：处理消息边界

SSE 以 `\n\n` 分隔消息，但网络不保证按消息边界分块：

```
理想情况: "data: {\"content\":\"你好\"}\n\n"
          ↑ 一条完整消息

实际情况: "data: {\"content\":\"你好"
          ↑ 半条！JSON 被截断了
```

buffer 的工作原理：
```typescript
buffer += decoder.decode(value, { stream: true });

// 按 \n\n 切割
const parts = buffer.split("\n\n");

// 最后一段可能不完整，存回 buffer 等下次拼接
buffer = parts.pop() || "";

// 前面的都是完整消息，逐条处理
for (const part of parts) {
  parseSSEChunk(part);
}
```

这样保证了只有拼成完整的 `data: {...}\n\n` 才会被解析，半条消息留在 buffer 里等下一次。

## 六、打字机效果的实现本质

用户看到的打字机效果：
```
你好 -> 你好！ -> 你好！有什么 -> (停顿) -> 你好！有什么问题 -> ...
```

这**不是**后端延迟发送每个字，而是数据自然分块到达后，前端逐块追加渲染。

核心代码：
```typescript
if (content) {
  setMessages((prev) => {
    return prev.map((item) =>
      item.id === assistantMsg.id
        ? { ...item, content: item.content + content }
        : item,
    );
  });
}
```

每次收到一个文本片段，就按临时 ID 追加到本次请求的 AI 消息 `content` 上。React 检测到 state 变化，重新渲染消息气泡，用户就看到文字在不断增长。

### 不可变更新模式

```typescript
setMessages((prev) => {
  return prev.map((item) =>
    item.id === assistantMsg.id
      ? { ...item, content: item.content + content }  // 创建新对象
      : item,
  );
});
```

React 要求状态更新必须返回新引用（不能直接修改原对象）。这里通过扩展运算符创建新数组和新对象，确保 React 能检测到变化。

## 七、中断生成（停止按钮）

### 7.1 AbortController

```typescript
const controller = new AbortController();
abortRef.current = controller;

// 绑定到 fetch
const res = await fetch("/api/chat", {
  ...
  signal: controller.signal,
});
```

### 7.2 stop 函数

```typescript
const stop = useCallback(() => {
  abortRef.current?.abort();  // 触发中断
  setIsLoading(false);
}, []);
```

用户点击"停止生成"时，`controller.abort()` 立即中断 fetch 请求。已接收的内容保留在界面上，后续未到达的数据被丢弃。

### 7.3 中断的异常处理

`abort()` 会触发 `AbortError`：
```typescript
} catch (e) {
  const err = e as Error;
  if (err.name !== "AbortError") {
    // 真实错误：显示错误信息
    setMessages(...);
  }
  // AbortError：静默处理，不显示错误
}
```

关键：`AbortError` 是用户主动触发的，不是真正的错误，所以静默处理。只有其他异常才显示错误提示。

## 八、错误处理策略

| 错误类型 | 表现 | 处理方式 |
|---------|------|---------|
| HTTP 错误（401/404/500） | `res.ok` 为 false | 抛出异常，在 AI 气泡显示 |
| LLM 调用失败 | SSE 返回 `{"error": "..."}` | 抛出异常，在 AI 气泡显示 |
| 用户中断 | `AbortError` | 静默处理，保留已收到的内容 |
| 网络断开 | fetch 抛出 `TypeError` | 在 AI 气泡显示 "[请求失败]" |

错误显示位置：如果 AI 气泡还是空的，把错误信息填入气泡；如果已有部分内容，保留已收到的内容（不覆盖）。

```typescript
prev.map((item) =>
  item.id === assistantMsg.id && !item.content
    ? { ...item, content: "[请求失败] " + err.message }  // 只有气泡为空时才填入
    : item,
);
```

## 九、临时 ID 生成

```typescript
const generateId = () =>
  Date.now().toString(36) + Math.random().toString(36).slice(2, 8);
```

发送消息时创建的用户消息和 AI 占位消息是临时对象，没有数据库 ID。用时间戳（36 进制）+ 随机串生成唯一字符串作为 React key。

**为什么用 `useRef` 存 AbortController？**
```typescript
const abortRef = useRef<AbortController | null>(null);
```
AbortController 不需要触发重渲染（它只是 fetch 的控制句柄），所以用 ref 而非 state。ref 的值变化不会导致组件重新渲染。

## 十、完整数据流图

```
用户点击发送
    |
    v
1. 立即更新 UI: 用户消息 + AI 空气泡
    |
    v
2. fetch POST /api/chat (带 AbortController)
    |
    v
3. 后端返回 StreamingResponse (SSE)
    |
    v
4. reader.read() 读取二进制块 (Uint8Array)
    |
    v
5. decoder.decode(value, {stream:true}) 转字符串
    |  (处理多字节字符截断)
    v
6. buffer += decoded; split("\n\n"); pop()
    |  (按 SSE 边界切割，不完整的留 buffer)
    v
7. parseSSEChunk(part) 提取 content/error/done
    |
    v
8. setMessages: 追加 content 到 AI 消息
    |  (React 重渲染 -> 打字机效果)
    v
9. 回到步骤 4，直到 done=true 或收到 [DONE]
    |
    v
10. finally: setIsLoading(false)
```

整个循环在几百毫秒内执行几十次，每次追加一小段文字，用户看到的就是流畅的打字机效果。
