# 前端架构与项目结构

> 本文档详细介绍前端的整体架构、目录结构、以及各模块的职责划分。

---

## 一、技术栈

| 技术 | 作用 |
|------|------|
| React 18 | UI 框架，使用函数组件 + Hooks |
| TypeScript | 类型安全，编译时发现错误 |
| Vite 5 | 构建工具 + 开发服务器（HMR 热更新） |
| Ant Design 5 | UI 组件库（表单、菜单、按钮、Avatar 等） |
| react-markdown | 将 AI 回复的 Markdown 渲染为 HTML |
| remark-gfm | GitHub 扩展语法支持 |
| react-syntax-highlighter | 代码块语法高亮 |

### 为什么选 Vite 而不是 CRA

Create React App (CRA) 已停止维护。Vite 是目前 React 社区的主流选择：
* 启动速度极快（原生 ESM，不需要打包）
* 热更新 (HMR) 几乎即时
* 配置简单，开箱即用

## 三、架构分层

```
┌─────────────────────────────────────────────┐
│              组件层 (Components)              │
│  LoginPage / Sidebar / MessageList            │
│  MarkdownRenderer                            │
│  纯展示，通过 props 接收数据，触发回调          │
├─────────────────────────────────────────────┤
│              Hooks 层 (State)                 │
│  useAuth / useConversations / useChat         │
│  封装状态管理和业务逻辑，调用 API 层            │
├─────────────────────────────────────────────┤
│              API 层 (HTTP)                    │
│  lib/api.ts                                  │
│  JWT token 管理，统一的 fetch 封装             │
├─────────────────────────────────────────────┤
│              类型层 (Types)                   │
│  types/index.ts                              │
│  前后端字段对齐                               │
└─────────────────────────────────────────────┘
```

### 为什么用 Hooks 封装状态

不把状态和逻辑写在组件里，而是抽到自定义 Hook 中：

* **组件保持简洁**：`App.tsx` 只负责组合组件和传递 props
* **逻辑可复用**：Hook 可以在多个组件中使用
* **关注点分离**：认证逻辑、对话管理、聊天逻辑各自独立

```typescript
// App.tsx 中的使用方式
const { user, loading, login, register, logout } = useAuth();
const { conversations, activeId, create, remove } = useConversations(!!user);
const { messages, input, isLoading, sendMessage, stop } = useChat(activeId);
```

三个 Hook 各管一摊，组件代码非常清晰。

## 四、Vite 配置详解

`vite.config.ts`：

```typescript
export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: {
      // 把 /api 开头的请求代理到后端，解决跨域
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true,
      },
    },
  },
})
```

### 代理的作用

开发时前端跑在 `localhost:5173`，后端跑在 `localhost:8000`。直接请求会有跨域问题。

Vite 代理的原理：
```
前端: fetch("/api/chat")
        ↓
Vite Dev Server 拦截 /api 开头的请求
        ↓
转发到 http://localhost:8000/api/chat
        ↓
响应返回前端
```

前端代码中写 `/api/chat`，Vite 自动转发到后端，浏览器认为请求是同源的（都是 5173），没有跨域问题。

**注意：** 生产环境不用 Vite Dev Server，需要用 Nginx 反向代理或后端 CORS 处理。

## 五、全局样式与设计 Token

`index.css` 定义了 CSS 变量（Design Tokens），整个项目共用：

```css
:root {
  --accent: #10a37f;        /* 主色调：ChatGPT 绿 */
  --accent-hover: #0d8c6d;
  --text: #0d0d0d;          /* 主文本色 */
  --text-secondary: #5d5d5d;
  --text-tertiary: #8e8e8e;
  --sidebar-bg: #f9f9f9;
  --bubble-user: #f4f4f4;   /* 用户消息气泡背景 */
  --bubble-ai: #ffffff;     /* AI 消息气泡背景 */
  --radius-md: 12px;
  --content-width: 1000px;
}
```

所有组件引用这些变量（如 `var(--accent)`），改一个地方就能全局生效。

### CSS Modules

每个组件配一个 `.module.css` 文件，类名自动加哈希后缀避免冲突：

```typescript
import styles from "./App.module.css";
// 使用: <div className={styles.layout}>
// 编译后: <div class="App_layout__a1b2c">
```

### Ant Design 主题定制

```typescript
<ConfigProvider
  theme={{
    token: {
      colorPrimary: "#10a37f",   // 与全局 --accent 一致
      borderRadius: 8,
      fontFamily: "...",
    },
  }}
>
```
通过 `ConfigProvider` 覆盖 Ant Design 默认主题，主色调改为项目统一的绿色。

## 六、应用根组件 App.tsx

`App.tsx` 是整个前端的中枢，根据登录状态决定渲染什么：

```typescript
export default function App() {
  const { user, loading, login, register, logout } = useAuth();

  // 1. 加载中：全屏 Spin
  if (loading) return <Spin />;

  // 2. 未登录：显示登录页
  if (!user) return <LoginPage onLogin={login} onRegister={register} />;

  // 3. 已登录：显示聊天界面
  return (
    <div className={styles.layout}>
      <Sidebar ... />
      <div className={styles.main}>
        <MessageList ... />
        <InputArea ... />
      </div>
    </div>
  );
}
```

条件渲染让认证状态驱动整个 UI 的切换，不需要 React Router。

## 七、类型定义 types/index.ts

前后端的字段保持对齐：

```typescript
// 后端 Pydantic ConversationRead  →  前端 Conversation
export interface Conversation {
  id: number;
  title: string;
  created_at: string;
  updated_at: string;
}

// 后端 MessageRead  →  前端 ServerMessage
export interface ServerMessage {
  id: number;
  role: Role;
  content: string;
  created_at: string;
}

// 前端渲染用的 Message（id 用 string 兼容临时消息）
export interface Message {
  id: string;
  role: Role;
  content: string;
}
```

**为什么前端 Message 的 id 是 string？** 前端会创建临时消息（发送时立即显示），临时消息没有数据库 ID，用时间戳+随机数生成的字符串做 key。
