# 用户认证系统

> 本文档详细介绍 fastapi-users 库的集成、JWT 认证的实现原理，以及各组件的协作关系。

---

## 一、认证方案概述

**用户决策：** "认证用现成库。"

本项目使用 **fastapi-users** 库实现完整的用户认证体系，核心包含：

* **JWT（JSON Web Token）**：无状态 token 认证
* **Bearer 传输**：前端在 HTTP Header 中携带 token
* **密码哈希**：bcrypt 算法（不存明文密码）

### 为什么用 JWT 而不是 Session

| 特性 | JWT（本项目） | Session |
|------|-------------|---------|
| 存储 | 前端 localStorage | 后端内存/Redis |
| 扩展性 | 天然支持多服务器 | 需要共享 Session 存储 |
| 登出 | 靠过期时间（1小时） | 立即失效 |
| 复杂度 | 低 | 中 |

对于前后端分离项目，JWT 更简洁。

## 二、fastapi-users 架构

fastapi-users 由四个核心组件组成，它们通过依赖注入串联：

``+┌──────────────────────────────────────────────────────────┐
│                    前端请求                                │
│            Authorization: Bearer <token>                  │
└────────────────────────┬─────────────────────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────────────────────┐
│  current_active_user (依赖)                               │
│  从请求中提取 token，校验，查出用户                         │
│                                                          │
│  调用链:                                                  │
│  current_active_user                                     │
│    → fastapi_users.current_user(active=True)             │
│      → auth_backend (JWT 策略)                            │
│        → get_jwt_strategy()  解码 token                   │
│        → bearer_transport   提取 token                    │
│      → get_user_manager()    查用户                       │
│        → get_user_db()       数据库适配器                  │
│          → get_async_session()  数据库 Session            │
└──────────────────────────────────────────────────────────┘
```

### 2.1 数据库适配器 `user_manager.py` - get_user_db

```python
async def get_user_db(
    session: AsyncSession = Depends(get_async_session),
) -> AsyncGenerator[SQLAlchemyUserDatabase, None]:
    yield SQLAlchemyUserDatabase(session, User)
```

这是 fastapi-users 与 SQLAlchemy 之间的桥梁。`SQLAlchemyUserDatabase` 封装了用户相关的数据库操作（增删改查、按邮箱查找等）。

### 2.2 用户管理器 `user_manager.py` - UserManager

```python
class UserManager(UUIDIDMixin, BaseUserManager[User, uuid.UUID]):
    reset_password_token_secret = settings.SECRET_KEY
    verification_token_secret = settings.SECRET_KEY

    async def on_after_register(self, user, request=None):
        print(f"User {user.id} has registered.")
```

`UserManager` 是认证的核心：
* `UUIDIDMixin`：使用 UUID 作为用户 ID
* `BaseUserManager`：提供用户创建、密码哈希、token 生成等方法
* `on_after_register`：注册后的回调钩子（可扩展为发邮件等）
* `reset_password_token_secret` / `verification_token_secret`：用于生成重置密码和邮箱验证的 token

```python
async def get_user_manager(
    user_db: SQLAlchemyUserDatabase = Depends(get_user_db),
) -> AsyncGenerator[UserManager, None]:
    yield UserManager(user_db)
```

### 2.3 认证后端 `backend.py`

```python
# Bearer 传输：前端在 Authorization 头中携带 token
bearer_transport = BearerTransport(tokenUrl="api/auth/jwt/login")

def get_jwt_strategy() -> JWTStrategy:
    """JWT 签名策略：token 有效期 1 小时"""
    return JWTStrategy(secret=settings.SECRET_KEY, lifetime_seconds=3600)

auth_backend = AuthenticationBackend(
    name="jwt",
    transport=bearer_transport,
    get_strategy=get_jwt_strategy,
)
```

认证后端 = 传输方式 + 签名策略：
* **BearerTransport**：token 从 `Authorization: Bearer xxx` 头中读取
* **JWTStrategy**：用 `SECRET_KEY` 签名/验证 token，有效期 3600 秒（1小时）

### 2.4 fastapi-users 实例 `router.py`

```python
fastapi_users = FastAPIUsers[User, uuid.UUID](get_user_manager, [auth_backend])

# 核心依赖：获取当前活跃用户
current_active_user = fastapi_users.current_user(active=True)
```

`FastAPIUsers` 是总入口，绑定了用户模型、用户管理器和认证后端。通过它可以生成各种路由。

`current_active_user` 是一个 FastAPI 依赖，用法：
```python
@router.get("/conversations")
async def list_conversations(
    user: User = Depends(current_active_user),  # 需要登录才能访问
):
    ...
```

如果请求没有 token、token 无效、或用户未激活，fastapi-users 自动返回 401。

## 三、路由注册

在 `main.py` 中注册 fastapi-users 提供的三组路由：

```python
# 1. 注册路由
app.include_router(
    fastapi_users.get_register_router(UserRead, UserCreate),
    prefix="/api/auth",
    tags=["auth"],
)
# 生成: POST /api/auth/register

# 2. 认证路由（登录/登出）
app.include_router(
    fastapi_users.get_auth_router(auth_backend),
    prefix="/api/auth/jwt",
    tags=["auth"],
)
# 生成: POST /api/auth/jwt/login, POST /api/auth/jwt/logout

# 3. 用户管理路由
app.include_router(
    fastapi_users.get_users_router(UserRead, UserUpdate),
    prefix="/api/users",
    tags=["users"],
)
# 生成: GET /api/users/me, PATCH /api/users/me, etc.
```

## 四、Pydantic Schema

`users/schemas.py` 定义了请求和响应的数据格式：

```python
class UserRead(schemas.BaseUser[uuid.UUID]):
    """返回给前端的用户信息（不含密码）"""
    created_at: datetime

class UserCreate(schemas.BaseUserCreate):
    """注册请求体"""
    pass

class UserUpdate(schemas.BaseUserUpdate):
    """更新请求体"""
    pass
```

fastapi-users 的 Base 系列类提供了标准字段：
* `BaseUserCreate`：`email` + `password`（注册时用）
* `BaseUser`：`id` + `email` + `is_active` + `is_superuser` + `is_verified`（读取时用）
* `BaseUserUpdate`：`password` + `email` + `is_active` + `is_superuser` + `is_verified`（更新时用）

`UserRead` 继承 `BaseUser` 并加了 `created_at`，这样前端能拿到注册时间。

## 五、JWT 工作原理

### 5.1 登录流程

```
前端 POST /api/auth/jwt/login
  Body: username=user@example.com&password=xxx  (表单格式)
        │
        ▼
后端:
  1. 从表单提取 username（实际是 email）和 password
  2. 通过 get_user_db 从数据库查出用户
  3. 用 bcrypt 校验密码: verify_password(password, user.hashed_password)
  4. 密码正确 → 用 SECRET_KEY 签发 JWT
  5. 返回 {"access_token": "eyJhb...", "token_type": "bearer"}
```

### 5.2 JWT 结构

JWT 由三部分组成（用 `.` 分隔）：
``
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhYmNAZC5jb20iLCJleHAiOjE3...}.SflKxwRJSMeKKF2QT4f...
|------ Header -------||-------------------- Payload -------------------||--- Signature ---|
```

* **Header**：算法类型（HS256）
* **Payload**：用户 ID（`sub`）、过期时间（`exp`）等
* **Signature**：用 SECRET_KEY 对 Header + Payload 的签名

### 5.3 后续请求验证

```
前端 GET /api/conversations
  Header: Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
        │
        ▼
后端 (current_active_user 依赖):
  1. bearer_transport 从 Authorization 头提取 token
  2. get_jwt_strategy() 解码 token，验证签名和过期时间
  3. 从 payload 提取 user_id（sub 字段）
  4. get_user_manager 通过 user_id 从数据库查出用户
  5. 检查 is_active 是否为 True
  6. 全部通过 → 注入 User 对象到路由参数
``+
如果任何一步失败，自动返回 401 Unauthorized。

## 六、安全注意事项

### 6.1 SECRET_KEY

`.env` 中的 `SECRET_KEY` 用于 JWT 签名。如果泄露，攻击者可以伪造任意 token。

生成强密钥：
```bash
openssl rand -hex 32
```

### 6.2 密码哈希

fastapi-users 默认使用 bcrypt（自带盐值），不需要手动处理盐值。即使数据库泄露，攻击者也无法从哈希反推明文密码。

### 6.3 CORS 与 Credentials

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],  # 不能用 *
    allow_credentials=True,
)
```
`allow_credentials=True` 时，`allow_origins` 不能是 `*`，必须指定具体域名。
