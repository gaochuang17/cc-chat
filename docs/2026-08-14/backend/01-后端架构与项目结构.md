# 后端架构与项目结构

> 本文档详细介绍后端的整体架构、目录结构、以及各模块的职责划分。

---

## 一、架构分层

后端采用经典的 **三层架构**，每层职责清晰：

```
┌─────────────────────────────────────────────┐
│              路由层 (API Layer)               │
│  接收 HTTP 请求，返回响应                      │
│  api/chat.py, api/conversations.py           │
│  users/router.py                             │
├─────────────────────────────────────────────┤
│              业务层 (Service Layer)           │
│  核心业务逻辑                                  │
│  core/config.py (配置)                       │
│  core/llm.py (LLM 调用)                      │
│  users/user_manager.py (用户管理)            │
├─────────────────────────────────────────────┤
│              数据层 (Data Layer)              │
│  数据模型与持久化                              │
│  models/ (ORM 模型)                          │
│  db/database.py (引擎与 Session)             │
│  SQLite (chat.db)                            │
└─────────────────────────────────────────────┘
```

### 为什么这样分层

- **路由层** 只关心 HTTP 协议（接收参数、返回响应），不写业务逻辑
- **业务层** 封装核心逻辑，可被多个路由复用
- **数据层** 只管数据的存储和读取，不知道谁在调用它

这种分层让代码更容易测试和维护。比如换掉 LLM 提供商，只需要改 `core/llm.py`，不影响路由层。

## 三、核心模块说明

### 3.1 入口文件 `main.py`

FastAPI 应用入口，职责：

1. 创建 `FastAPI` 实例
2. 注册 CORS 中间件（允许前端跨域访问）
3. 注册所有路由（聊天、对话、认证、用户管理）
4. 提供健康检查接口 `/`

```python
app = FastAPI(title="AI Assistant API", version="0.1.0")

# CORS: 允许 localhost:5173（Vite 开发服务器）访问
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# 路由注册，统一加 /api 前缀
app.include_router(chat_router, prefix="/api")
app.include_router(conversation_router, prefix="/api/conversations")
app.include_router(fastapi_users.get_register_router(...), prefix="/api/auth")
app.include_router(fastapi_users.get_auth_router(...), prefix="/api/auth/jwt")
app.include_router(fastapi_users.get_users_router(...), prefix="/api/users")
```

**关键设计：** CORS 只允许 `localhost:5173`，生产环境应改为具体前端域名。

### 3.2 配置管理 `core/config.py`

采用简单的类配置模式，从 `.env` 文件读取：

```python
load_dotenv()  # 加载 .env 文件

class Settings:
    OPENAI_API_KEY: str = os.getenv("OPENAI_API_KEY", "")
    OPENAI_BASE_URL: str = os.getenv("OPENAI_BASE_URL", "https://api.openai.com/v1")
    OPENAI_MODEL: str = os.getenv("OPENAI_MODEL", "gpt-4o-mini")
    SECRET_KEY: str = os.getenv("SECRET_KEY", "dev-secret-change-me")
    DATABASE_URL: str = os.getenv("DATABASE_URL", "sqlite+aiosqlite:///./chat.db")

settings = Settings()  # 全局单例
```

其他模块通过 `from app.core.config import settings` 获取配置。

**设计考量：**
- 没有用 Pydantic Settings（BaseSettings），因为这个项目足够简单
- `load_dotenv()` 不传路径参数，依赖 CWD 是 `backend/` 目录（已知限制）

### 3.3 LLM 调用 `core/llm.py`

封装 OpenAI SDK，提供延迟初始化和流式调用：

```python
_client = None  # 全局客户端，延迟初始化

def get_client() -> AsyncOpenAI:
    """延迟初始化，避免没有 API key 时服务器无法启动"""
    global _client
    if _client is None:
        _client = AsyncOpenAI(api_key=..., base_url=...)
    return _client

async def stream_chat_raw(messages: list[dict]):
    """调用 LLM 并逐 token 流式返回原始文本（不含 SSE 格式）"""
    client = get_client()
    response = await client.chat.completions.create(
        model=settings.OPENAI_MODEL,
        messages=messages,
        stream=True,  # 关键：开启流式
    )
    async for chunk in response:
        delta = chunk.choices[0].delta
        if delta.content:
            yield delta.content  # 只返回文本片段
```

**关键设计：**
- **延迟初始化**：`get_client()` 在第一次调用时才创建客户端，避免服务器启动时因缺少 API key 而崩溃
- **职责单一**：`stream_chat_raw` 只负责调用 LLM 和返回文本，SSE 格式化交给路由层

### 3.4 启动脚本 `run.py`

```python
if __name__ == "__main__":
    uvicorn.run("app.main:app", host="0.0.0.0", port=8000, reload=True)
```

等价于命令行 `uvicorn app.main:app --reload`。`reload=True` 开发模式自动热重载。

## 四、FastAPI 的核心概念

### 4.1 依赖注入（Depends）

FastAPI 用 `Depends` 实现依赖注入，是整个后端最重要的模式：

```python
# 定义依赖：每个请求创建一个数据库 Session
async def get_async_session() -> AsyncGenerator[AsyncSession, None]:
    async with async_session_maker() as session:
        yield session

# 在路由中使用：参数声明 + Depends
@router.get("/conversations")
async def list_conversations(
    db: AsyncSession = Depends(get_async_session),      # 注入数据库 Session
    user: User = Depends(current_active_user),          # 注入当前登录用户
):
    ...
```

FastAPI 自动管理依赖的生命周期：请求开始时创建 Session，请求结束后自动关闭。

### 4.2 Pydantic 模型

FastAPI 用 Pydantic 做请求体验证和响应序列化：

```python
class ChatRequest(BaseModel):
    conversation_id: int
    message: str = Field(min_length=1)  # 不能为空字符串
```

请求进来时，FastAPI 自动验证：
- `conversation_id` 必须是整数
- `message` 不能为空（min_length=1）
- 验证失败自动返回 422 + 详细错误信息

### 4.3 路由前缀与标签

```python
app.include_router(conversation_router, prefix="/api/conversations", tags=["conversations"])
```

- `prefix`：所有路由自动加上 `/api/conversations` 前缀
- `tags`：OpenAPI 文档分组（访问 `/docs` 可看到分组效果）

## 五、API 路由一览

| 方法 | 路径 | 功能 | 认证 |
------|------|------|------|
| POST | `/api/auth/register` | 注册 | 否 |
| POST | `/api/auth/jwt/login` | 登录 | 否 |
| POST | `/api/auth/jwt/logout` | 登出 | 是 |
| GET | `/api/users/me` | 获取当前用户 | 是 |
| POST | `/api/conversations` | 创建对话 | 是 |
| GET | `/api/conversations` | 列出对话 | 是 |
| GET | `/api/conversations/{id}/messages` | 获取历史消息 | 是 |
| DELETE | `/api/conversations/{id}` | 删除对话 | 是 |
| POST | `/api/chat` | 流式聊天 | 是 |

启动后端后访问 `http://localhost:8000/docs` 可查看自动生成的交互式 API 文档。

## 六、Python 3.9 兼容性注意

项目运行在 Python 3.9.6，有以下语法限制：

| 语法 | Python 3.9 | Python 3.10+ |
|------|-----------|-------------|
| 联合类型 | `Optional[str]` / `Union[A, B]` | `str \| None` / `A \| B` |
| 类型标注 | `list[dict]` 可用（PEP 585） | 同左 |
| `match` 语句 | 不支持 | 支持 |

代码中使用 `typing.Optional` 和 `typing.Union` 而非 `X | Y` 语法。
