## 本次更改概览

本次在原有按会话缓存聊天状态的基础上，重构了会话选中与新会话首次发送
流程：

1. 当前选中的会话只保存在 `chatStore.activeConversationId`；
2. `useConversations` 不再维护 `activeId`，只负责会话列表；
3. `useChat` 不再通过 effect 同步选中值或触发历史请求，只读取当前会话的
   selector 并暴露 store action；
4. `selectExistingConversation(id)` 用于点击已有会话，内部按需调用
   `loadHistory(id)`；
5. `adoptCreatedConversation(newId)` 用于创建接口返回后建立空缓存并选中
   新会话，不请求历史；
6. 新会话首次发送按显式顺序执行：`createConversation()` ->
   `adoptCreatedConversation(newId)` -> `sendMessage(newId)` ->
   `refreshConversations()`；
7. `adoptCreatedConversation` 会中断并移除同 ID 的旧流式 controller，
   防止后端数据重置复用数字 ID 时旧响应污染新缓存；
8. 更新 `AGENTS.md` 的注释规则，并排查本次改动范围内的抽象注释，改为说明
   具体字段、函数、请求和时序。

## 本次目标

1. 支持会话 A 流式生成中切换到会话 B，再切回 A 后继续查看流式结果；
2. 将消息、请求状态、历史状态和输入草稿按会话隔离，避免全局 `messages`
   被当前投影覆盖；
3. 修复新对话首次发送的草稿来源错误；
4. 阻止旧 SSE 请求、旧历史请求把内容写回已删除、已停止、已重发或已切换
   账号的会话状态；
5. 收到 SSE `[DONE]` 后终止事件循环和读取循环，并释放响应流；
6. 保护会话列表不被慢响应、旧列表快照或旧账号数据覆盖。
7. 新会话首次发送不请求必然为空的会话历史。
8. 注释和开发文档与当前源码保持一致。

## 核心结果

| 模块                          | 结果                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------- |
| `chatStore.ts`                | 按会话缓存聊天状态；持有当前会话 ID；使用 controller 和登录缓存版本号隔离旧响应 |
| `useChat.ts`                  | 读取当前会话 selector；暴露 store action；处理账号缓存重置                      |
| `App.tsx`                     | 组织选择、草稿、新会话注册和发送的显式调用顺序                                  |
| `useConversations.ts`         | 只管理会话列表；使用登录状态标识和列表版本标识校验响应                          |
| `MessageList` / `MessageItem` | 使用 memo 和滚动策略降低长对话流式渲染成本                                      |

`sendMessage` 的最终调用约定：

```text
sendMessage()
  发送到当前选中会话，读取 chats[activeId].draftInput

sendMessage(newId)
  只用于新对话首次发送，读取顶层 draftInput
```

流式响应每次修改状态前都由 `canWriteCurrentStream()` 校验登录缓存版本号、
abort 状态、controller 是否仍是本次请求，以及 `chats[id]` 是否仍存在。
历史请求返回时同样会拒绝跨账号、已删除或已有更新本地消息的响应。
