# 2026-08-18 开发概览

## 合并说明

本文档目录已合并 2026-08-17 的聊天状态改造内容和 2026-08-18 的
`sendMessage` 异步时序修复内容。合并后的文档以当前代码为准，去除了重复
描述和已过期的旧修复快照。

## 本次目标

1. 支持会话 A 流式生成中切换到会话 B，再切回 A 后继续查看流式结果；
2. 将消息、请求状态、历史状态和输入草稿按会话隔离，避免全局 `messages`
   被当前投影覆盖；
3. 修复新对话首次发送的草稿来源错误；
4. 阻止旧 SSE 请求、旧历史请求把内容写回已删除、已停止、已重发或已切换
   账号的会话状态；
5. 收到 SSE `[DONE]` 后终止事件循环和读取循环，并释放响应流；
6. 保护会话列表不被慢响应、旧列表快照或旧账号数据覆盖。

## 核心结果

| 模块                          | 结果                                                       |
| ----------------------------- | ---------------------------------------------------------- |
| `chatStore.ts`                | 按会话缓存聊天状态；使用 controller 和缓存代数隔离异步写回 |
| `useChat.ts`                  | 作为 React 适配层，负责 selector 投影、历史触发和账号重置  |
| `App.tsx`                     | 区分 `sendMessage()` 与 `sendMessage(newId)` 的调用语义    |
| `useConversations.ts`         | 使用 session/list opaque token 保护列表写回                |
| `MessageList` / `MessageItem` | 使用 memo 和滚动策略降低长对话流式渲染成本                 |

`sendMessage` 的最终调用约定：

```text
sendMessage()
  发送到当前选中会话，读取 chats[activeId].draftInput

sendMessage(newId)
  只用于新对话首次发送，读取顶层 draftInput
```

旧请求写回统一由 `canWriteCurrentStream()` 校验账号代数、abort 状态、
controller 归属和会话缓存是否存在。历史请求返回时同样会拒绝跨账号、已删除
或已被乐观发送更新的视图。
